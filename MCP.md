# MCP-сервер редактора «Проклятых Земель» — руководство для ИИ

`mcp.js` даёт ИИ-агенту (Claude Code, Claude Desktop, любой MCP-клиент) все функции редактора: карты и объекты, существа и патрули, скрипты карт, рельеф и текстуры земли, базу данных, тексты, квесты и диалоги, зоны и переходы, модели, текстуры, бэкапы. Сервер работает без браузера и без `server.js`: он сам читает и пишет файлы игры теми же модулями, что и редактор.

Этот документ написан для агента. Человеку достаточно раздела «Подключение».

---

## 1. Подключение

Нужен Node.js 18+. Сервер — stdio, команда `node "<путь>/Editor/mcp.js"`.

**Claude Code.** В папке `Editor` уже лежит `.mcp.json`. Чтобы сервер был доступен в любой папке:

```bash
claude mcp add --scope user ei-editor -- node "C:/GOG Games/EI_edit/Editor/mcp.js"
```

**Claude Desktop.** Добавьте в `%APPDATA%\Claude\claude_desktop_config.json`:

```json
{ "mcpServers": { "ei-editor": { "command": "node", "args": ["C:/GOG Games/EI_edit/Editor/mcp.js"] } } }
```

Папку игры сервер берёт так же, как редактор: `../Evil Islands` или `gameDir` из `Editor/config.json`. Переменная окружения `EI_GAME_DIR` её переопределяет, это удобно для опытов на копии игры.

Проверка: `node tools/mcp-test.mjs` копирует нужные файлы игры во временную папку и прогоняет все инструменты по протоколу MCP. Настоящие файлы при этом не меняются.

## 2. Правила, которые нужно знать до первой правки

1. **Правки сразу пишутся в файлы игры.** Отдельной кнопки «Сохранить» нет. Перед первым изменением файла его оригинал копируется в `Editor/backup/`, а новые файлы попадают в список созданных. `backups_list` показывает изменённые файлы, `backups_restore {path}` возвращает оригинал одного файла, `backups_restore {all: true}` откатывает всё и удаляет созданное. Полный откат стирает и правки человека, поэтому без его просьбы не выполняйте его.
2. **Браузерный редактор и MCP — разные процессы.** Если человек держит открытым в браузере тот же файл с несохранёнными правками, его «Сохранить» затрёт ваши изменения. Перед большой работой предупредите его.
3. **Правки не проверены в самой игре.** Форматы проверены побайтовыми round-trip-тестами на всех файлах игры, но запуск `game.exe` никто не автоматизировал. После заметной правки предложите человеку `game_launch` и проверку.
4. **Сначала читайте, потом пишите.** Узнайте точные имена через `*_list`, `*_search` и `*_get`. Сервер ничего не угадывает и вернёт ошибку со списком допустимых значений.
5. **Имена файлов, зон, моделей и текстур пишутся латиницей** (`[a-z0-9_]`). Тексты для игрока пишутся по-русски: они хранятся в cp1251, так что эмодзи и редкие символы потеряются.
6. **Объекты карт связаны со скриптами по id.** В скриптах встречается `GetObjectByID( "1281" )` или имя объекта. Удаление такого объекта ломает скрипт, поэтому перед `map_object_delete` поищите id и имя в `map_script_get`.
7. **Записи базы связаны по имени.** Карты, другие таблицы и скрипты ссылаются на имена прототипов и предметов. Переименование или удаление записи может уронить игру.
8. **Инструменты выполняются строго по очереди.** Параллельные вызовы ставятся в очередь.

## 3. Модель мира

### Острова, зоны, файлы

- **Острова (allod):** `gipat` (Гипат), `ingos` (Ингос), `suslanger` (Суслангер).
- **Зона** — блок в `Res/texts.res → map.txt`. Посмотреть: `zones_list`, `zone_get`. Типы зон:
  - `game` — игровая карта;
  - `brief` — база с брифингами;
  - `edge` — переход между зонами по глобальной карте.
- У игровой зоны есть `#res <mpr> <mob>`, например `zone1 zone1`:
  - `Maps/<mpr>.mpr` — ландшафт (рельеф, текстуры земли, вода);
  - `Maps/<mob>.mob` — объекты, существа, рычаги, свет, звуки, скрипт и граф проходимости.
- Другие `.mob` на том же ландшафте — варианты карты: `zone12dm1.mob`, квестовые `z3q1.mob` для сетевой игры. Инструменты сами подбирают к ним `.mpr`. Если подбор не сработал, передайте `mpr` явно.
- **Сетевые квесты** — `Maps/*.mq`. Это RES-архив с текстами `quest …` и `briefing …` и с конфигом `<имя>\quest.reg` (награды, выдаваемые квесты).
- **Одиночная и сетевая игра** используют разные базы и тексты: `source: "sp"` (по умолчанию) — `database.res` и `texts.res`, `source: "mp"` — `databaselmp.res` и `textslmp.res`.

### Координаты

- 1 единица = **1 метр**. `x` растёт на восток (вправо на `terrain_render`), `y` — на север (вверх на картинке), `z` — высота.
- Ландшафт состоит из секторов 32×32 м. Карта размером `sectors [8, 6]` имеет площадь 256×192 м, вершины рельефа стоят через 1 м.
- **Тайл текстуры земли** занимает 2×2 м. Код тайла: `atlas*64 + index`. Атлас — текстура `<mpr>000.mmp…<mpr>007.mmp` из 8×8 тайлов. Биты 14–15 кода задают поворот (`rot` 0–3 по 90°).
- **Позиция объекта** — `[x, y, высота НАД землёй]`. Обычно третья координата равна 0: объект стоит на земле. Если передать `pos: [x, y]`, высота над землёй сохранится прежней.
- **Точки патруля** хранятся с абсолютной высотой. `map_patrol_set` берёт её с рельефа сам, вы передаёте только `[x, y]`.
- **Поворот** `yaw` задаётся в градусах вокруг вертикали.
- **Максимальная высота** карты (`terrain_info.max_height`, обычно 20–50 м) — потолок рельефа. Всё выше обрезается.

### Граф проходимости

В основном `.mob` зоны хранится граф проходимости: где могут ходить 8 классов существ. Сервер пересчитывает его сам в двух случаях:

- после правки рельефа (`terrain_sculpt`, `terrain_set_heights`, `terrain_import_heightmap`) — вокруг изменённого места;
- после добавления, сдвига или удаления статичного объекта — вокруг объекта.

В ответе это видно по полю `path_graph_nodes_rebuilt`. Существа граф не меняют, тайлы земли тоже. Правила построения подобраны по оригинальным картам и совпадают с графом Nival на 84–91%.

## 4. Инструменты

Все параметры передаются JSON-объектом. Ответ — JSON-текст, а у `terrain_render` и `texture_export` ещё и PNG-картинка. При ошибке ответ помечается `isError` и содержит понятное сообщение.

### Общее

| Инструмент | Что делает |
|---|---|
| `game_info` | Папка игры, списки `.mob`, `.mpr`, `.mq` и `Res/*.res`, число изменённых файлов. **Начинайте с него.** |
| `backups_list` | Изменённые файлы и созданные файлы (с пометкой `(новый)`). |
| `backups_restore {path}` / `{all: true}` | Откат одного файла или всего. |
| `game_launch` | Запуск `game.exe`. |
| `res_list {path, query?}` | Записи RES-архива: `Res/*.res`, `Maps/*.mpr`, `Maps/*.mq`. |
| `res_read {path, name, as}` | Чтение записи: `text` (cp1251), `reg` (INI-текст), `hex` или `base64`. |
| `res_write {path, name, text \| reg \| base64 \| delete}` | Запись, создание или удаление записи архива. |

### Тексты, квесты, диалоги

| Инструмент | Что делает |
|---|---|
| `texts_search {query?, group?, source?}` | Поиск по ключу и тексту. `group` — первое слово ключа: `quest`, `briefing`, `unit`, `weapon`, `armor`, `spell`, `perk`, `zone`, `string`, `tip`, `material`, `questitem`, `qitem`… |
| `texts_get {names[]}` | Полные тексты по ключам. |
| `texts_set {entries: [{name, text}], delete?: []}` | Создать, изменить или удалить. `\n` сами превращаются в `\r\n`. |

Ключ текста — «категория + id», например `unit goblina1` → «Гоблин с пращой». Первая строка текста обычно содержит название, дальше идёт описание.

**Квест** (`quest <id>`):

```
Название квеста
Описание квеста (одна или несколько строк).
#subobj  1
Название подзадачи 1
Описание подзадачи 1
#subobj  2
Название подзадачи 2
Описание подзадачи 2
```

**Брифинг-диалог** (`briefing <id>`):

```
Заголовок брифинга
#show Elder 3            // показать персонажа в слоте 3
#show Hero 5
#CAMERA 4                // ракурс камеры
#phrase Elder  1         // реплика: кто говорит, номер по порядку
Текст реплики (может занимать несколько строк).
#ANIMATION 45            // жест говорящего
#phrase Hero  2
Ответ героя.
#hide Elder              // убрать персонажа
#NOLIPS                  // следующая реплика без движения губ
#DESC Себе под нос       // ремарка
```

Чтобы получить правильные имена персонажей (`Hero`, `Elder`, `bGoblinC`…), номера камер и анимаций, возьмите похожий оригинальный брифинг через `texts_search {group: "briefing"}` и меняйте его.

**Награды сетевого квеста** лежат в `quest.reg` внутри `.mq`. Читайте его через `res_read {path: "Maps/z3q1.mq", name: "z3q1\\quest.reg", as: "reg"}`, а записывайте через `res_write {…, reg: "<тот же формат>"}`:

```ini
[quest]
name=z3q1
exp:i=0
money:i=0
questplaces={148;185}

[briefing receive]
name=z3q1_1
give quests[]=q.z3q1.z3q1

[briefing complete]
name=z3q1_3
exp:i=150
```

Суффикс `:i` означает целое число, `:f` — дробное, `[]` — повторяющийся ключ.

### База данных (предметы, существа, магия)

| Инструмент | Что делает |
|---|---|
| `db_tables {source?}` | Все таблицы: файл, id, имя, число записей. |
| `db_records {file, table, query?, offset?, limit?}` | Записи: `[индекс, имя, …первые поля]`. |
| `db_record_get {file, table, record}` | Все поля: `id`, `name`, `type`, `text` (значение), `desc`. Вложенные поля — в `sub`. |
| `db_record_set {file, table, record, fields}` | `fields: {"Price": "500", "D.Min": "4"}`. Ключ — имя или id поля, для вложенного поля `"Поле.Подполе"`. Значения передаются текстом в том же виде, в каком их показал `db_record_get`. |
| `db_record_add {file, table, from, name}` | Новая запись копированием образца. Имя должно быть уникальным. |
| `db_record_delete {file, table, record}` | Удаление записи. Помните про ссылки на неё. |
| `units_list {query?}` | Прототипы существ с моделью расы — для `map_object_add`. |

`record` — индекс (число) или внутреннее имя записи без учёта регистра.

| Файл | Таблицы (id) |
|---|---|
| `items.idb` | 1 материалы · 2 оружие · 3 доспехи и одежда · 4 зелья и свитки · 5 квестовые предметы · 6 трофеи |
| `units.udb` | 1 зоны попадания · 2 расы и модели · 3 монстры · 4 НПС |
| `spells.sdb` | 1 заклинания · 2 модификаторы · 3 шаблоны заклинаний · 4 шаблоны для доспехов · 5 шаблоны для оружия |
| `perks.pdb` | 1 навыки · 2 умения |
| `levers.ldb` | 1 рычаги, двери, сундуки |
| `quests.qdb` | 1 награды за квесты · 2 награды за брифинги |
| `prints.db`, `acks.db` | следы; реплики-отклики существ |

Типы значений: `String`, `UnsignedLong`, `Float`, списки через запятую, `BitList` — строка из `0` и `1`. `Hex` — сырые байты через пробел: их лучше не трогать.

Название предмета для игрока хранится не в базе, а в текстах: `weapon <имя>`, `armor <имя>`, `unit <имя>`. Новому предмету нужна и запись в базе, и текст.

### Карты: объекты, существа, патрули, скрипты

| Инструмент | Что делает |
|---|---|
| `map_objects {mob, kind?, query?, near?: [x, y, r]}` | Список объектов. `kind`: `unit`, `object`, `lever`, `trap`, `effect`, `light`, `sound`, `particles`. |
| `map_object_get {mob, id}` | Все свойства, у существ ещё снаряжение и маршруты. |
| `map_object_set {mob, id, fields}` | Изменить свойства, передавая только меняемые поля (см. список ниже). |
| `objects_catalog {query?}` | Каталог статичных объектов со всех зон игры (деревья, дома, камни, заборы…): `proto`, `model`, `texture` и сколько раз объект встречается. |
| `map_object_add {mob, unit, fields: {pos}}` | Новое существо из базы на любую карту, даже пустую. Модель, текстура и телосложение берутся по расе. **Снаряжение берётся с шаблона** — задайте `weapons` и `armors`. |
| `map_object_add {mob, object, fields: {pos}}` | Статичный объект из `objects_catalog` (по прототипу или модели) или своя импортированная модель (по имени из `models_list`). |
| `map_object_add {mob, copy_of: id, fields?}` | Копия объекта этой же карты: рычага, сундука, ловушки, света — вместе со всеми настройками. |
| `map_object_delete {mob, id}` | Удаление объекта. |
| `map_patrol_set {mob, id, points: [[x, y]…], wait?, guard?}` | Маршрут патруля целиком. |
| `map_script_get {mob}` / `map_script_set {mob, script}` | Скрипт карты. |

Поля в `fields`: `name`, `prototype`, `unit` (прототип существа), `model`, `texture`, `pos`, `yaw`, `complection` (`[сила, ловкость, рост]` от 0 до 1), `player` (сторона), `quest_info`, `visible`, `use_in_script`, `weapons`, `armors`, `spells`, `quick_items`, `quest_items` (списки имён из базы).

**Скрипт карты.** Язык скриптов ПЗ состоит из блоков:

- `GlobalVars ( имя : object, … )` — глобальные переменные;
- `DeclareScript Имя ( this : object )` — объявления;
- `Script Имя ( … )` — триггеры (`if`/`then`);
- `WorldScript ( … )` — выполняется при загрузке. Сюда пишут `GetObjectByID( "id" )` и `GSSetVar( 0, "z.<зона>", 2 )` (открыть переход).

Скрипт перезаписывается целиком, поэтому сначала прочитайте его, потом меняйте точечно. Образцы есть в любой оригинальной карте, например `zone2`.

### Ландшафт

| Инструмент | Что делает |
|---|---|
| `terrain_info {mpr}` | Размер, максимальная высота, перепад высот, атласы, `tiles_by_type` (какие тайлы — трава, камень…), самые частые тайлы. |
| `terrain_heights {mpr, x0, y0, x1, y1, step?}` | Сетка высот в метрах. `rows[0]` — строка `y0`. |
| `terrain_render {mpr, mob?, x0…y1?, size?}` | **PNG-вид сверху:** текстуры, тени рельефа, вода, сетка секторов 32 м, существа красными точками, прочие объекты жёлтыми. Смотрите на него после каждой серии правок. |
| `terrain_sculpt {mpr, ops: […]}` | Лепка рельефа пачкой операций. |
| `terrain_set_heights {mpr, x0, y0, step, rows, blend?}` | Рельеф целиком по сетке опорных высот с плавной интерполяцией. |
| `terrain_import_heightmap {mpr, png_path, min?, max?, x0…y1?}` | Рельеф из серой PNG (чёрный = `min`, белый = `max`). Верх картинки — север. |
| `terrain_paint {mpr, ops: […]}` | Покраска текстурой земли. |
| `terrain_tile_import {mpr, tile, png_path, type?}` | Своя текстура земли: PNG кладётся в тайл атласа, `type` задаёт тип земли. |

Операции `terrain_sculpt` выполняются по порядку. Форма операции — круг `{x, y, radius}` с мягким краем или прямоугольник `{x0, y0, x1, y1}` с полной силой:

| `tool` | Действие |
|---|---|
| `raise` / `lower` | поднять или опустить на `amount` метров (по умолчанию 1) в центре |
| `flatten` | выровнять к высоте центра или к `height` |
| `set` | поставить высоту `height` |
| `smooth` | сгладить, `amount` — число проходов (1–20) |
| `noise` | природные неровности ±`amount` м, `seed` — вариант |

Операция `terrain_paint` состоит из формы (круг или прямоугольник, радиус по умолчанию 2 м) и того, что класть. Варианты:

- `tile: 65` — конкретный тайл;
- `atlas: 1, index: 3` — тайл по атласу и номеру;
- `tiles: [12, 13, 14]` — случайный тайл из списка;
- `type: "grass"` — случайный тайл этого типа.

`rot` принимает 0–3 или `"random"`. Случайные тайлы и повороты убирают заметные повторы.

Типы земли (`type`, по-английски или по-русски): `0 grass трава`, `1 ground земля`, `2 stone камень`, `3 sand песок`, `4 rock скала`, `5 field поле`, `6 water вода`, `7 road дорога`, `8 empty пусто`, `9 snow снег`, `10 ice лёд`, `11 dry grass сухая трава`, `12 drifts сугробы`, `13 lava лава`, `14 swamp болото`, `15 high rock высокая скала`. На карте есть только те типы, что перечислены в `terrain_info.tiles_by_type`.

**Своя текстура земли.** Каждая клетка атласа — 64×64 пикселя. Видна её середина 48×48, края по 8 пикселей служат запасом для фильтрации. `terrain_tile_import` масштабирует PNG до 48×48 и заполняет края повтором, поэтому бесшовные текстуры стыкуются без швов. Атлас принадлежит ландшафту по имени, то есть меняется у всех `.mob` на этом `.mpr`. Чтобы не испортить оригинальную зону, меняйте тайлы на своей новой зоне: мастер создаёт ей собственные копии атласов.

Вода пока не редактируется: её не умеют ни браузерный редактор, ни MCP. На ландшафте, скопированном из зоны-образца (`relief: "copy"`), вода сохраняется.

### Зоны

| Инструмент | Что делает |
|---|---|
| `zones_list {allod?}` | Список зон: id, остров, тип, `#res`, переходы `номер→куда#вход`. |
| `zone_get {id}` / `zone_set {id, text}` | Блок `map.txt` целиком. |
| `zone_create {id, file, allod, tpl, relief?, sx?, sy?, link?, title?, open?}` | Новая зона, как мастер в редакторе. |

`zone_create` делает следующее:

- создаёт ландшафт `Maps/<file>.mpr`: ровный размером `sx×sy` секторов (от 2 до 16) или копию рельефа образца `tpl`;
- создаёт `Maps/<file>.mob` с пустым скриптом и графом проходимости;
- копирует атласы земли и миникарту зоны `tpl`;
- добавляет блок в `map.txt`;
- если задан `link`, добавляет переход из этой зоны (`edge`-зону `<link>_<id>`), а при `open` (по умолчанию) открывает его в скрипте соседней зоны.

После создания поправьте в `zone_get` прямоугольник `#deploy` — место, где появится отряд.

Директивы блока `map.txt`:

| Директива | Значение |
|---|---|
| `#res` | файлы `mpr mob` |
| `#maps` | размер в секторах; текстуры миникарты и карты целей |
| `#position` | точка на глобальной карте |
| `#weather` | `none`, `rain` или `snow` |
| `#sky` | `normal` или `cave` |
| `#exit N` | `соседняя_зона номер_входа_там` |
| `#deploy` / `#remove` | прямоугольники `x1 y1 x2 y2` |
| `#view` | угол камеры |
| `#passtime` | время перехода |

### Модели и текстуры

| Инструмент | Что делает |
|---|---|
| `models_list {query?}` | Модели из `figures.res`. |
| `model_info {name}` | Части, вершины, треугольники, габариты основания, есть ли анимации. |
| `model_import_obj {name, obj_path, texture_path?, scale?, y_up?, to_ground?, overwrite?}` | Статичная модель из OBJ: здание, дерево, предмет. Каждый `o`/`g` в файле становится частью модели. Существ с анимацией так не сделать — для них нужен Blender и `ei_figer` из папки `Files`. |
| `textures_list {source?, query?}` | Текстуры: `textures` (мир, модели, атласы), `redress` (одежда), `menus`. |
| `texture_export {name, source?, save_to?}` | Показать текстуру как PNG и при желании сохранить файл. |
| `texture_import {name, png_path, source?}` | Заменить текстуру (масштабируется под исходный размер) или создать новую (размер берётся из PNG, лучше степень двойки). |

PNG читается 8-битный, без interlace. JPG и другие форматы сначала сохраните как PNG.

## 5. Рецепты

**Новая зона с островным рельефом**

1. `zones_list` — выбрать образец `tpl` с подходящими текстурами (например `gz1g`, лес Гипата) и соседа `link`.
2. `zone_create {id: "gz30g", file: "myisle", allod: "gipat", tpl: "gz1g", relief: "flat", sx: 6, sy: 6, link: "gz1g"}`.
3. `terrain_info {mpr: "myisle"}` — узнать размер (192×192 м), максимальную высоту и тайлы по типам.
4. `terrain_set_heights` — опорная сетка через 32 м: центр выше, к краям ниже. Затем `terrain_sculpt` с `noise` (amount 0.7) и `smooth`.
5. `terrain_paint` — сначала вся карта `type: "grass"` с `rot: "random"`, потом склоны `type: "stone"`, дорога `type: "road"` прямоугольниками вдоль пути, у воды `sand`.
6. `terrain_render {mpr: "myisle"}` — посмотреть результат и поправить.
7. `zone_get` → поправить `#deploy` → `zone_set`.

**Заселить зону**

1. `units_list {query: "orc"}`.
2. `map_object_add {mob: "myisle", unit: "<имя>", fields: {pos: [100, 120], yaw: 180, weapons: […], armors: […]}}`.
3. `map_patrol_set {mob: "myisle", id: <id>, points: [[100, 120], [130, 120], [130, 150]]}`.
4. Деревья и дома: `objects_catalog {query: "tree"}`, затем `map_object_add {mob: "myisle", object: "<proto>", fields: {pos: [x, y], yaw: 30}}`. Разный `yaw` и чуть разные позиции делают лес естественнее.
5. `terrain_render {mpr: "myisle", mob: "myisle"}` — проверить расстановку.

**Новое оружие**

1. `db_records {file: "items.idb", table: 2, query: "sword"}` — найти образец.
2. `db_record_add {…, from: "<образец>", name: "mysword"}`.
3. `db_record_set {…, record: "mysword", fields: {Price: "900", "D.Min": "8", "D.Max": "14"}}`.
4. `texts_get {names: ["weapon <образец>"]}`, затем `texts_set {entries: [{name: "weapon mysword", text: "Меч Рассвета\nОписание…"}]}`.
5. Выдать: `map_object_set {…, fields: {weapons: [..., "mysword"]}}` или положить в `quest.reg`.

**Новый сетевой квест со диалогом** — скопируйте существующий `.mq`: прочитайте его записи через `res_list` и `res_read`, затем `res_write` в новый `Maps/<имя>.mq`. Поменяйте `quest`, `briefing` и `quest.reg` по форматам из раздела 4.

**Своя текстура земли**

1. Подготовить бесшовную PNG.
2. `terrain_info` — выбрать редко используемый тайл своей зоны.
3. `terrain_tile_import {mpr: "myisle", tile: 61, png_path: "…", type: "grass"}`.
4. `terrain_paint {ops: [{x, y, radius, tile: 61, rot: "random"}]}`.

**Своя модель на карте**

1. `model_import_obj {name: "mytower", obj_path: "…/tower.obj", texture_path: "…/tower.png", scale: 1}`.
2. `map_object_add {mob, object: "mytower", fields: {pos: [x, y], name: "tower1"}}`. Текстура по умолчанию берётся с тем же именем, что и модель.

**Откат.** `backups_list`, затем `backups_restore {path: "Maps/zone1.mob"}` для одного файла. Полный откат — `{all: true}`, только по прямой просьбе человека.

## 6. Ограничения

- Вода, свет (`light`), звуки (`sound`) и частицы (`particles`) читаются и сохраняются как есть. Двигать их можно, но отдельных полей у них нет, а воду создать нельзя.
- Импорт моделей только статичный: без скелета и анимаций.
- Граф проходимости строится по подобранным правилам, поэтому на изменённых участках существа могут ходить чуть иначе, чем в оригинале.
- Новый остров целиком (новый `allod` с фигурами глобальной карты) не поддерживается. Делайте новые зоны на существующих островах.
- Ничего из этого не проверено запуском игры. Предлагайте человеку проверить мод после крупных правок.
